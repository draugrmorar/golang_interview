# СТРОКИ

Строка физически - это **массив байтов**. По умолчанию строки кодируются в UTF-8 в языке Go.
Строка логически - это **массив рун**.

Строка состоит из двух составляющих: это **указатель на массив байт** и **длина массива**.
При передаче строки не копируется весь текст, передается только указатель и длина (16 байт на 64-битной системе).

**Строка иммутабельна (Immutable)**

---

## Руны
- **Rune** - это псевдоним для `int32`
- Литерал типа данных rune - это **одинарные кавычки**.
- `runes := []rune("Хай")` - сделать строку массивом рун

---

## strings.Builder{}
Для построения строк этот подход менее затратный чем конкатенация. Для построения новых строк, перестроения старых, склеивания и т.д.

```go
builder := strings.Builder{}
builder.WriteString(strconv.Itoa(i))
str := builder.String()
```

---

## strconv.Itoa(i) / strconv.Atoi()
"Integer to ASCII" / "ASCII to Integer"

Использовать эти функции для превращения чисел в строки и обратно, так как в случае явного приведения типа, приведение происходит байт, а не рун.

---

## Подстрока из строки
Делается так же как создаются слайсы. Но тут опять не следует забывать что строка это массив байт. Подстрока начинает указывать на элемент из старой строки — это помешает памяти очистить старую строку. Как решение этой проблемы лучше создать копию:

```go
firstWord := string([]byte(message[:5]))
firstWord := strings.Clone(message[:5]) // Go1.18
```

---

## Обратные кавычки ``
Обратные кавычки сохраняют расставленные переносы строк, не схлопывают пробелы и позволяют удобно расставлять внутри себя одинарные и двойные кавычки без экранирования.

---

## Сравнение строк

- **оператор `==`** — производительный, быстрее чем `strings.Compare()`
- **`strings.Compare()`** — самый медленный способ сравнения строк, возвращает `-1/0/1` (первая строка меньше второй / строки равны / первая строка больше второй)
- **`strings.EqualFold()`** — самый производительный, но он **не учитывает регистр**, поэтому можно использовать если регистр не важен

# МАССИВЫ

Массив — коллекция элементов одного типа. **Длина массива не может изменяться**.

Если мы создадим два массива в Go с разными длинами, то два массива будут иметь **разные типы**, так как длина массива в Go входит в его тип.

Копируется при передаче в другую переменную или при отправке в другую область видимости.

```go
arr := [4]int{3,2,5,4} // создание массива
```

## Копирование
Копирование массива — это просто присвоение одного массива другому. Поскольку в Go массив ведет себя как значение, а не как ссылка, то изменение любого значения одного массива не оказывает никакого влияния на другой.

## Сравнение
Два массива называются равными, если они оба имеют одинаковый тип и размер, имеют одинаковые элементы, и все элементы находятся в одинаковом порядке в обоих массивах.

# СЛАЙСЫ

Срезы (slice) представляют последовательность элементов одного типа переменной длины. В отличие от массивов длина в срезах не фиксирована и динамически может меняться, то есть можно добавлять новые элементы или удалять уже существующие.

```go
bar := []byte{} // создание слайса
```

Способ с `make` является более интересным, так как дает нам возможность задать тип, длину и емкость.

## Строение слайса под капотом

```go
struct {
    array *[]T // ссылка на исходный массив
    length int
    capacity int
}
```

## len() и cap()
- **len()** — длина слайса. Общее количество элементов, которые содержит срез.
- **cap()** — емкость среза — это количество элементов в базовом массиве, начиная с первого элемента среза. Это означает, что емкость среза относится к размеру, до которого может быть расширен срез.

## append
Добавляет элементы в конец среза (slice), автоматически управляя базовым массивом.
- Если емкости (capacity) достаточно, она просто увеличивает длину (length) и записывает данные.
- Если места нет, она создает новый массив большего размера, копирует туда старые данные и добавляет новые.

Динамически расширяясь, емкость (cap) нового слайса растет в два раза для маленьких слайсов (до 256), а потом емкость растет в 1.25–1.5 раза.

## копирование copy()
Эта функция принимает два аргумента: исходный срез, который мы хотим скопировать, и целевой срез, в который мы хотим скопировать элементы. Она всегда возвращает целочисленное число, которое представляет количество скопированных элементов. Возвращаемое значение всегда является минимальной длиной исходного среза и целевого среза.

## сортировка
Несколько методов сортировки для среза по типам: `sort.Ints()`, `sort.Float64s()` и `sort.Strings`. Эти методы сортировки всегда сортируют срез в порядке возрастания.

## поиск
`sort.SearchInts()`, `sort.SearchFloat64s()` и `sort.SearchStrings`. Эти функции выполняют двоичный поиск в отсортированном срезе в порядке возрастания. Если элемент найден в отсортированном срезе, функция поиска возвращает его индекс; если нет, она возвращает индекс, по которому элемент будет помещен в срез.

## сравнение
Два среза считаются равными, если они хранят данные одного типа и содержат одни и те же элементы. Go предоставляет функцию `reflect.DeepEqual(slice1, slice2)`.

### 1. Внутренняя структура слайса

Слайс представляет собой структуру данных фиксированного размера (24 байта на 64-битных системах):

```go
type sliceHeader struct {
    Data uintptr   // указатель на первый элемент в массиве
    Len  int       // текущая длина (количество элементов)
    Cap  int       // максимальная емкость без перевыделения памяти
}
```

**Ключевые следствия:**
- Слайс не владеет данными — он всегда ссылается на существующий массив
- Передача слайса в функцию копирует только 24 байта независимо от объема данных
- Изменение элементов через индекс влияет на оригинал (общий массив)
- Изменение `len` или `cap` через `append` в функции не влияет на вызывающий код (копируется структура)

### 2. Создание слайса: способы и последствия

| Способ | Код | Len | Cap | Выделение памяти |
|--------|-----|-----|-----|------------------|
| nil-слайс | `var s []T` | 0 | 0 | нет (Data=nil) |
| Литерал | `[]T{a,b,c}` | 3 | 3 | массив на 3 элемента |
| make (len) | `make([]T, 5)` | 5 | 5 | массив на 5 элементов |
| make (len, cap) | `make([]T, 0, 10)` | 0 | 10 | массив на 10 элементов |

**Почему необходим `make`:** явно инициализирует внутренний массив. `var s []T` создает nil-слайс без памяти.

### 3. Алгоритм роста емкости при append

При превышении `cap` Go выделяет новый массив по правилам:

- **Если cap < 1024:** новая емкость = текущая × 2
- **Если cap >= 1024:** новая емкость = текущая + текущая/4 (рост на 25%)

**Цена каждой переаллокации:**
1. Выделение нового блока памяти
2. Копирование всех существующих элементов
3. Освобождение старого блока (ожидание GC)

### 4. Оптимизация через предварительное выделение емкости

**Без указания емкости (переаллокации):**
```go
var ids []int
for i := 0; i < 1000; i++ {
    ids = append(ids, i)  // ~10 переаллокаций, ~5000 копирований
}
```

**С предварительным выделением:**
```go
ids := make([]int, 0, 1000)
for i := 0; i < 1000; i++ {
    ids = append(ids, i)  // 0 переаллокаций, 0 копирований
}
```

**При точном знании размера (оптимально):**
```go
ids := make([]int, 1000)  // len=1000, cap=1000
for i := 0; i < 1000; i++ {
    ids[i] = i  // прямая индексация, без append
}
```

### 5. Создание слайса через срез: полная форма с третьим индексом

Стандартный срез `original[low:high]` создает слайс:
- `len = high - low`
- `cap = cap(original) - low` (до конца исходного массива)

**Полная форма с третьим индексом:** `original[low:high:max]`

```go
original := make([]int, 10, 20)  // len=10, cap=20

s1 := original[2:5]      // len=3, cap=18 (20-2)
s2 := original[2:5:7]    // len=3, cap=5  (7-2)
```

**Свойства третьего индекса:**
- Ограничивает емкость нового слайса: `cap = max - low`
- Должен удовлетворять: `low <= high <= max <= cap(original)`
- Защищает от случайного записи в родительский массив при `append`

**Практическое применение:**
```go
func main() {
    parent := make([]int, 5, 10)
    for i := 0; i < 5; i++ {
        parent[i] = i
    }
    
    s1 := parent[2:5]       // указывает на parent[2:5]
    s2 := parent[2:5:5]     // cap=3, изолирован
    
    s1 = append(s1, 100)    // изменяет parent[5] (перезаписывает)
    s2 = append(s2, 200)    // выделяет новый массив, parent не затронут
}
```

### 6. Утечки памяти при срезах

Создание маленького слайса от большого массива удерживает весь родительский массив в памяти:

```go
func getFirst(data []byte) []byte {
    return data[0:1]  // ПЛОХО: удерживает весь data в памяти
}

func getFirstSafe(data []byte) []byte {
    result := make([]byte, 1)
    copy(result, data[0:1])
    return result  // ХОРОШО: копирует только нужный байт
}
```

**Когда это критично:** чтение больших файлов, работа с буферами сетевых пакетов, парсинг больших JSON.

### 7. Резюме: правила эффективной работы

1. **Передавайте слайсы свободно** — копируется только структура (24 байта)
2. **Используйте `make` с `cap`** если ожидаемый размер известен (даже приблизительно)
3. **При точном знании размера** используйте `make([]T, n)` с прямой индексацией
4. **Используйте третий индекс** для ограничения `cap` и изоляции слайсов
5. **Копируйте данные** если нужен только маленький фрагмент от большого массива
6. **Избегайте избыточного `cap`** при большом количестве слайсов (проблемы кэширования CPU)

# МАПЫ

## Что это
Хэш-таблица — это структура данных, ассоциативный массив. Она позволяет хранить пары «ключ-значение». Хэш-таблица нужна для хранения и организации информации с помощью хэш-функции.

- В качестве ключа можно использовать любой тип данных для которого определена операция сравнения. Например, можно использовать структуру с тем же условием для всех ее полей.
- При отсутствии элемента возвращается нулевое значение для типа. Вторым параметром можно получить флаг наличия элемента по ключу.
- Нельзя получить адрес элемента. Потому что при росте мапы оно переедет в другой бакет и адрес у него, соответственно, поменяется.
- Мапа не безопасна для конкурентного использования. Для этого можно использовать обертку из `sync.Map` или мьютекс.
- Порядок итерации не сохраняется. При каждой новой итерации мапы последовательность возвращаемых элементов может отличаться. Под капотом каждый раз выбирается рандомный бакет, с которого начинается итерация. Для сохранения нужного порядка придется сохранять ключи в отдельном массиве и итерироваться по нему.
- При каждом создании мапы генерируется seed для рандомизации хэш-функции. Это сделано для безопасности, так как зная хэш-функцию можно подобрать такие ключи, что все значения попадут в один бакет и мы получим линейную скорость поиска.
- При коллизиях используется стратегия closed addressing. Мы перебираем все ячейки бакета (их 8) и ищем первое свободное место.
- OverloadFactor равен 6.5 (~81% заполненности бакетов). Когда бакеты в среднем заполнены больше чем на 6.5 элементов, триггерится рост мапы, и все элементы перемещаются в новые бакеты, которых создается в два раза больше.
- При росте элементы переносятся в новые бакеты постепенно, а не все сразу.
- **В Go 1.24+ мапа поменялась и внутренняя логика тоже**.

## Мапа строение структуры

```go
type hmap struct {
    count     int // размер мапы. используется функцией len()
    flags     uint8
    B         uint8  // log_2 количества бакетов. Для 8 бакетов B=3, для 16 B=4 и так далее.
    noverflow uint16 // примерное число переполненных бакетов
    hash0     uint32 // seed для хэш-функции, генерируется при создании мапы. Нужен для рандомизации хэш-функции
    buckets    unsafe.Pointer // ссылка на массив из 2^B бакетов; nil, если count==0
    oldbuckets unsafe.Pointer // ссылка на массив предыдущих бакетов.
                              // в процессе роста мапы здесь будет массив старых бакетов,
                              // откуда потихоньку будут переноситься значения в новые бакеты.
    nevacuate  uintptr        // количество "эвакуированных" бакетов.
    extra *mapextra // опциональные поля
}

// Бакет
type bmap struct {
    tophash [bucketCnt]uint8     // массив, содержит 8 верхних байт хэшей каждого ключа в бакете.
                                 // Для оптимизации поиска храним массив первых восьми бит от хэша ключа
                                 // После массива tophash идет массив размера bucketCnt ключей и
                                 // массив размера bucketCnt элементов.
}
```

## Мапа строение логическое

Состоит из **бакетов**: в бакете 8 элементов. Количество бакетов записано в переменной B — log₂, то есть для того чтобы понять сколько бакетов нужно возвести 2 в степень B.

В бакете есть переменные LOB (low order bits) и HOB (high order bits) — для побитового поиска нужного бакета:
- **LOB** — помогает найти бакет
- **HOB** — помогает найти нужный слот

В бакете ключи и значения хранятся в виде списка. Сначала ключи, потом пустые слоты, потом значения (для выравнивания памяти).

Если бакет переполнен (все 8 значений), тогда создается новый бакет и старый бакет ссылается на него.

## Коллизии (способы решения / реиндексация)

Коллизия — это ситуация, когда два различных ключа имеют одинаковое хеш-значение и, как следствие, попадают в одну и ту же «корзину» (ячейку) массива данных.

**Способы решения коллизий:**

- **Открытая адресация**: Мы помещаем ключ в свободную ячейку, следующую за текущей или с определённым шагом. Поиск будет происходить в том же порядке, что и при вставке, и до тех пор, пока не будет найден элемент с искомым ключом или свободная ячейка.
- **Метод цепочек**: При использовании метода цепочек мы добавляем элементу в текущей ячейке ссылку на новый. Так появляются связь между предыдущим и новым элементами, образуется цепочка элементов с одинаковыми хэшами (двусвязный список).

**Сложность:** O(N)

## Сложность операций
O(1)

## Overflow-бакет
Это дополнительный бакет, который создается, когда основной бакет (и его стандартные 8 ячеек) переполняется. Фактически это "запасной" бакет, связанный с основным через указатель.

- Разрешение коллизий
- Предотвращение немедленного роста
- Баланс производительности и памяти

## load factor
Коэффициент заполняемости таблицы — это отношение количества хранимых пар «ключ-значение» к размеру таблицы. Если они достигают пограничного значения, то хэш-мапу расширяют, а индексы пар пересчитывают и перераспределяют.

## Расширение (Эвакуация)
Увеличение количества бакетов в Go и распределение существующих пар называется **эвакуацией**.

Рост мапы начинается в двух случаях:
- бакеты в среднем заполнены на больше чем ~80% (loadFactor равно 6.5)
- частный случай — количество overflow бакетов примерно равно количеству самих бакетов

При эвакуации количество бакетов увеличивается в два раза. Текущие пары с топхэшами распределяются по этим бакетам.

В Go используются два подхода, которые сводятся к увеличению количества бакетов:
- Увеличение общего количества бакетов и перераспределение пар по этим бакетам.
- Создание бакета, на который даём ссылку в заполненный бакет. Если понадобится записать в заполненный, то мы запишем в тот, на который есть ссылка.

**Три стратегии:**
- мапа не растет, и тогда программист выделяет мапу достаточного размера заранее
- мапа растет за время операции вставки, и некоторые вставки очень долгие
- данные переносятся в новую мапу в фоне — это процесс эвакуации

## Процесс эвакуации
Ключевая особенность реализации Go в том, что эвакуация происходит постепенно, во время штатных операций с map. Это сделано для того, чтобы избежать длительных stop-the-world при копировании большого объема данных.

1. **Инициализация роста (hashGrow)**: При срабатывании одного из триггеров вызывается функция hashGrow. Она выделяет память под новый массив бакетов в два раза большего размера. Поле oldbuckets начинает указывать на старый массив бакетов. Данные не копируются, только создается новый массив.

2. **Постепенная эвакуация (growWork и evacuate)**: Каждый раз при последующих операциях записи или удаления из map, вызывается функция growWork, которая запускает процесс эвакуации для 1-2 бакетов.

3. **Функция evacuate** выполняет перенос данных из одного конкретного старого бакета в новый массив.

4. **Поведение операций во время эвакуации**: Запись и удаление являются движущей силой процесса. Чтение проверяет, эвакуирован ли уже соответствующий старый бакет, и ищет данные там, где они актуальны.

5. **Окончание эвакуации**: Процесс продолжается до тех пор, пока все старые бакеты не будут перенесены. Когда эвакуация завершена, h.oldbuckets устанавливается в nil, и память, занятая старым массивом, становится доступной для GC.

## Алгоритм добавления элемента
В цикле ищем совпадения по tophash и ключу или свободное место. Сохраняем данные и возвращаем соответствующий флаг для подсчета элементов в мапе. Если не нашли нужного места, то повторяем упражнения на overflow бакете.

## Удаляем элемент
Вместо фактического удаления просто помечаем ячейку пустой.

## Итерация по мапе
Происходит магия "рандомной" последовательности элементов при каждой новой итерации: выбирается случайный бакет, с которого начнется итерация, и отступ, с которого будут возвращаться элементы внутри каждого бакета.

Алгоритм итерации можно разделить на две части:
- простой случай — когда мапа не в процессе роста
- сложный случай — в процессе роста (требуются дополнительные проверки)

## fmt.Println
Перед выводом сортирует мапу по возрастанию.

# МАПА Go 1.24+

## Различия с предыдущими версиями
- **Новая структура данных**
- **Отсутствие overflow-бакетов**
- **Тип решения коллизий**: раньше был закрытый тип индексации (цепочки переполнения), стал открытый (линейное/квадратичное пробирование)
- **Разный тип расширения**
- **load factor** был 80%, стал **87%**

## Новая структура данных
- **Slot (Слот)**: Самая маленькая единица — это пара "ключ-значение".
- **Group (Группа)**: Группа объединяет 8 слотов. Это аналог старого бакета, но теперь все группы в рамках одной таблицы имеют фиксированный размер.
- **Table (Таблица)**: Это и есть основная хеш-таблица, которая состоит из множества групп. Таблица имеет ограничение на максимальный размер (например, не более 1024 слотов или 128 групп).
- **Directory (Директория)**: Это массив указателей на таблицы. Когда одна таблица переполняется, создается новая, и указатель на нее добавляется в директорию. Выбор нужной таблицы происходит по первым битам хеша ключа (Extendible Hashing).

## Расширение
Рост инициируется, когда коэффициент загрузки (load factor) достигает **7/8 (87%)**.

- **Рост для небольших map** (до ~1024 элементов): создается новая таблица большего размера, все элементы немедленно перехешируются и копируются.
- **Рост для больших map** (более 1024 элементов) — расщепление таблиц (Extendible Hashing): создается новая таблица, часть элементов из переполненной таблицы перемещается в новую по старшим битам хеша.

## GOEXPERIMENT=noswissmap
Если хотите оставить старую имплементацию, выставите при сборке переменную окружения `GOEXPERIMENT=noswissmap`.

## Мапы в Go1.24 коротко
- Трехуровневая структура: каталог хеш-таблиц групп.
- Хеш-таблица с закрытой адресацией — каталог.
- Хеш-таблицы с открытой адресацией.
- Мапа растет сама. Скачок потребления памяти не очень большой, но память мапа не возвращает.
- Нет процесса эвакуации, рост за время одной операции вставки.
- Для ускорения поиска используется **SIMD**.
- Случайный порядок итерации по мапе.
- Нельзя взять указатель на значение в мапе.
- **loadFactor = 7/8 или 87,5%**.

# Не валидные операции с мапами и слайсами

| Операция | Map | Slice |
|----------|-----|-------|
| Чтение из nil | ✅ Безопасно (zero value) | ❌ Паника (index out of range) |
| Запись в nil | ❌ Паника | ❌ Паника (index out of range) ✅ Append работает |
| Сравнение с `==` | ✅ Только с nil | ✅ Только с nil |
| Адрес элемента | ❌ Компиляция запрещает | ✅ Можно |
| Конкурентный доступ | ❌ Race condition (кроме чтения) | ❌ Race condition (зависит от операций) |
| Отрицательный индекс | ❌ Компиляция запрещает | ❌ Компиляция запрещает |
